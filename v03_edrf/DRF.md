# Формат записи игры DRF

DRF (Digger Recording File) — запись партии в Digger. Формат придуман в
Digger Remastered, в этой версии он тот же: записи из браузера играются в
оригинальной игре, и наоборот.

## Главная идея

В записи нет ни картинки, ни положения монстров, ни счёта. В ней только две
вещи:

- **что нажимал игрок** в каждом кадре;
- **случайное число**, с которого начинался каждый раунд.

Этого хватает, потому что игра полностью предсказуема: при тех же нажатиях и
тех же случайных числах всё происходит точно так же, до пикселя. При
просмотре игра не воспроизводит видео, а играет заново, подставляя нажатия
из файла вместо клавиатуры.

Поэтому записи маленькие. Партия на 353 уровня — это 565 тысяч кадров,
около 12,5 часа игры — занимает 120 КБ.

Кадр (тик) — один шаг игры, их 12,5 в секунду.

## Как устроен файл

Это обычный текст, его можно открыть в любом редакторе. Файл состоит из двух
частей: заголовка и раундов.

### Заголовок

Первые 84 строки:

```
DRF
JS WEB 20261022
1
20000
S   B     HHHHS
V  CC  C  V B
...
```

| Строка   | Что в ней                                                     |
|----------|---------------------------------------------------------------|
| 1        | `DRF` — признак того, что это запись Digger                   |
| 2        | версия программы, которая записала файл                       |
| 3        | режим игры, см. ниже                                          |
| 4        | сколько очков нужно для дополнительной жизни, обычно 20000   |
| 5–84     | карты 8 уровней, по 10 строк из 15 символов                   |

**Режим игры:**

| Запись   | Режим                                         |
|----------|-----------------------------------------------|
| `1`      | один игрок                                    |
| `2`      | два игрока по очереди                         |
| `M2`     | два игрока одновременно                       |
| `G120`   | gauntlet: набрать как можно больше за 120 секунд |
| `M2G120` | gauntlet вдвоём                               |

В конце может стоять `I` и номер уровня, с которого начата игра: `1I5` —
один игрок с 5-го уровня.

**Карты** хранятся в самой записи, чтобы игра на своих картах тоже
воспроизводилась правильно. Символы на карте:

| Символ | Что это                          |
|--------|----------------------------------|
| `S`    | перекрёсток туннелей (обычно в верхних углах) |
| `H`    | горизонтальный туннель           |
| `V`    | вертикальный туннель             |
| `C`    | изумруд                          |
| `B`    | мешок с золотом                  |
| пробел | земля                            |

**Версия** нужна из-за одной старой ошибки. Важна только дата в ней (с 8-го
символа): записи до 25 ноября 1998 года сделаны программой, где монстры
двигались чуть иначе. Чтобы такие записи играли правильно, игра повторяет
ту ошибку.

### Раунды

Раунд — это кусок игры от начала уровня (или от появления Диггера после
смерти) до его конца: уровень пройден или Диггер погиб.

Пример раунда:

```
1E29A13D
s25r38u18Sl25s7
EOL
```

1. **`1E29A13D`** — случайное число раунда, 8 шестнадцатеричных цифр. От
   него зависит, как будут вести себя монстры.
2. **`s25r38u18Sl25s7`** — куда шёл Диггер в каждом кадре.
3. **`EOL`** (end of level) — конец раунда.

Направления записаны буквами:

| Буква | Направление           |
|-------|-----------------------|
| `s`   | стоять на месте       |
| `r`   | вправо                |
| `u`   | вверх                 |
| `l`   | влево                 |
| `d`   | вниз                  |

**Большая буква** значит, что в этом кадре нажат огонь: `S` — стоит и
стреляет, `R` — идёт вправо и стреляет.

**Число после буквы** — сколько кадров подряд было это направление. Нет
числа — один кадр. Так пример выше читается:

| Запись | Что было                        |
|--------|---------------------------------|
| `s25`  | 25 кадров стоял                 |
| `r38`  | 38 кадров шёл вправо            |
| `u18`  | 18 кадров шёл вверх             |
| `S`    | 1 кадр стоял и выстрелил        |
| `l25`  | 25 кадров шёл влево             |
| `s7`   | 7 кадров стоял                  |

Длинные раунды переносятся на несколько строк, примерно по 60 символов.
Переносы ничего не значат: они нужны, только чтобы файл было удобно
пересылать (по словам автора формата, по электронной почте).

Когда играют двое одновременно, буквы обоих Диггеров идут вперемешку, в том
порядке, в котором игра их спрашивала.

### Конец файла

После последнего раунда может быть:

| Запись | Что значит                                               |
|--------|----------------------------------------------------------|
| `EOG`  | (end of game) игрок вышел из игры клавишей Esc           |
| `*ABC` | игрок набрал рекорд и ввёл инициалы `ABC`                |

Если игра просто закончилась (кончились жизни), ни того, ни другого нет.

## Маленький пример целиком

```
DRF
JS WEB 20261022
1
20000
(80 строк карт)
1E29A13D
s25r38u18Sl25s7
EOL
EOG
```

Один игрок, один раунд: Диггер постоял, прошёл вправо и вверх, выстрелил,
ушёл влево, постоял и погиб. Игрок вышел клавишей Esc.

## Чего в записи нет

**Кадров, когда игра не спрашивала направление.** Направление пишется,
только когда Диггер может двигаться. Пока он мёртв или толкает мешок, кадры
в запись не попадают: при просмотре игра и сама их пропустит, раз всё
повторяется так же.

Из-за этого есть одна неточность: если нажать Esc в тот момент, когда
Диггер умирает, момент нажатия не сохранится. При просмотре раунд
доиграется до конца, и только тогда просмотр остановится.

**Звука, скорости и паузы.** Музыку, скорость игры и паузы можно менять как
угодно: на ход игры они не влияют.

## Где это в коде

- [web/js/record.js](web/js/record.js) — запись и чтение DRF;
- [tests/drf.mjs](tests/drf.mjs) — проверка: проигрывает записи из
  оригинальной игры и сравнивает счёт, уровень и число кадров с тем, что
  было в ней.
